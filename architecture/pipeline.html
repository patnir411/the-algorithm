Feature Categories:

  • Author Features: Reputation, verification, follower count, abuse strikes
  • Content Features: Text embeddings, entities, media, language
  • Engagement Features: Like/RT/reply counts, velocity, age-adjusted
  • Graph Features: User-author similarity (Real Graph), social connections
  • Embedding Features: SimClusters, TwHIN, Transformer embeddings
  • Temporal Features: Tweet age, hour of day, day of week
  • Real-time Aggregates: Hourly engagement statistics
  • Safety Features: NSFW scores, spam scores, toxicity scores
🔧 Hydration Strategy: Features are batched by service to minimize RPC calls. For example, all candidates' author features are fetched in a single batch call to the author service.

Stage 4.4: Score Reranking

Model predictions are aggregated using a weighted sum with per-head normalization.

📁 /home-mixer/functional_component/scorer/WeighedModelRerankingScorer.scala 
For each candidate:
  1. Normalize each signal by per-head maximum
     normalized_score_i = score_i / max(all_scores_i)

  2. Apply dynamic weights
     weighted_score_i = normalized_score_i × weight_i

  3. Aggregate
     final_score = Σ(weighted_score_i) + ε
     where ε = 0.001 (epsilon for precision)

  4. Sort candidates by final_score (descending)

Normalization

Per-Head Max Prevents single signal domination

Weights

Dynamic Feature-switch controlled

Range

-10K to +10K Per weight parameter

Result Selection & Filtering

Scored candidates go through sequential selectors that filter, deduplicate, and position content.

📁 /home-mixer/product/for_you/ForYouMixerPipelineConfig.scala:307-541

Selector Pipeline (30+ Steps)

  1. UpdateSortCandidates: Sort by final score (descending)
  2. UpdateConversationModuleId: Group conversation threads
  3. RemoveDuplicateCandidatesOutsideModule: Dedup video carousel
  4. DropMaxCandidates: Limit to top 35 scored tweets
  5. InsertAdResults: Inject ads at organic positions
  6. InsertFixedPositionResults: Add trends, stories at fixed positions
  7. DropOrthogonalCandidates: Remove non-tweet modules if needed
  8. DropModuleTooFewModuleItemResults: Ensure min module size
  9. UpdateSortModuleItemCandidates: Sort within modules
  10. Insert*: Various insertions for different content types
🎯 Key Insight: Selectors run sequentially in the order defined. Each selector transforms the candidate list before passing to the next.

Side Effects & Logging

After selection, the system executes side effects for tracking, analytics, and future optimization.

Side Effect Types

  • UpdateTimelinesPersistenceStoreSideEffect: Cache served tweets for deduplication
  • HomeScribeServedCandidatesSideEffect: Log served candidates to Scribe
  • ServedCandidateFeatureKeysKafkaSideEffect: Send feature keys to Kafka
  • UpdateLastNonPollingTime: Track user engagement timeline
  • PublishClientSentImpressions: Emit impression events
  • TruncateTimelinesPersistenceStoreSideEffect: Cleanup old cache
📊 Why Side Effects Matter: These logs feed into ML training pipelines, A/B testing analysis, and real-time monitoring dashboards.

Optimization Techniques

  • Parallel Execution: Stitch framework for async/concurrent operations
  • Batch Fetching: Group RPC calls by service to reduce latency
  • Caching: Multi-layer caching (Memcached, Manhattan, client-side)
  • Feature Switches: Gradual rollouts and A/B testing without deployment
  • Circuit Breakers: Fallback to cached/backup sources on failures
  • Request Sampling: Load shedding during high traffic
