📈 Ranking & Scoring System

Deep dive into engagement signals, weights, and score aggregation

🎯 The 15 Engagement Signals

Twitter's ranking model predicts 15 different types of user engagement. Each signal represents a probability (0.0 to 1.0) that a user will perform that action with the tweet.

📁 /home-mixer/server/src/main/scala/com/twitter/home_mixer/model/PredictedScoreFeature.scala
1. Favorite (Like) TIER 1
Probability the user will like/favorite the tweet. The most common engagement signal.
Feature PredictedFavoriteScore
Weight Param FavParam
2. Retweet TIER 1
Probability the user will retweet or quote tweet. Includes both regular retweets and quote tweets with commentary.
Feature PredictedRetweetScore
Weight Param RetweetParam
3. Reply TIER 1
Probability the user will reply to the tweet. Indicates strong engagement and conversation potential.
Feature PredictedReplyScore
Weight Param ReplyParam
4. Reply Engaged By Author TIER 3
Probability that if the user replies, the original tweet author will engage with that reply. Measures conversation quality.
Feature PredictedReplyEngagedByAuthorScore
Weight Param ReplyEngagedByAuthorParam
5. Bookmark TIER 2
Probability the user will bookmark/save the tweet for later. Indicates high-value content.
Feature PredictedBookmarkScore
Weight Param BookmarkParam
6. Share TIER 2
Probability the user will share the tweet (copy link, DM, or native share). Strong virality indicator.
Feature PredictedShareScore
Weight Param ShareParam
7. Good Click (Engagement) TIER 3
Probability of a "good" click: tweet detail view, photo expansion, or conversation thread click that leads to engagement.
Feature PredictedGoodClickConvoDescFavoritedOrRepliedScore
Weight Param GoodClickParam
8. Good Click with Dwell TIER 3
Click followed by meaningful dwell time (UAM > 2 seconds). Indicates content quality and user interest.
Feature PredictedGoodClickConvoDescUamGt2Score
Weight Param GoodClickUamGt2Param
9. Good Profile Click TIER 3
Profile click that results in engagement. Measures author discovery and follow potential.
Feature PredictedGoodProfileClickScore
Weight Param GoodProfileClickParam
10. Dwell Time TIER 1
Predicted time user will spend viewing the tweet. Normalized dwell time indicates content engagement.
Feature PredictedDwellScore
Weight Param DwellParam
11. Video Quality View TIER 4
Probability user will watch video for ≥10 seconds. Only applicable to video tweets ≥10s duration.
Feature PredictedVideoQualityViewScore
Weight Param VideoViewParam
12. Video Quality View Immersive TIER 4
Video quality view in immersive/fullscreen mode. Higher engagement than standard video view.
Feature PredictedVideoQualityViewImmersiveScore
Weight Param VideoViewImmersiveParam
13. Video Watch Time TIER 4
Predicted total watch time in milliseconds. Aggregated metric for video engagement quality.
Feature PredictedVideoWatchTimeScore
Weight Param VideoWatchTimeParam
14. Video Quality Watch TIER 4
Combined metric for high-quality video watchtime. Considers both duration and completion rate.
Feature PredictedVideoQualityWatchScore
Weight Param VideoQualityWatchParam
15. Negative Feedback NEGATIVE
Probability of negative actions: "Not interested", "Block author", "Mute author", or "Report tweet". Used to suppress low-quality content.
Feature PredictedNegativeFeedbackV2Score
Weight Param NegativeFeedbackV2Param

⚖️ Weight Parameter System

Each engagement signal has a dynamically adjustable weight controlled via feature switches. This enables A/B testing and real-time optimization without model retraining.

📁 /home-mixer/server/src/main/scala/com/twitter/home_mixer/param/HomeGlobalParams.scala

Weight Range Configuration

-10,000 0 +10,000

Negative weights: Suppress tweets with high probability
Zero weight: Ignore signal completely
Positive weights: Boost tweets with high probability

15 Independent Weight Parameters
Dynamic Adjustable via Feature Switches
±10,000 Weight Range
0.001 Epsilon (precision adjustment)
🔑 Key Insight: Weights are NOT fixed in the model. They're external parameters that can be modified in real-time. This allows Twitter to:
  • Run A/B tests on different weight configurations
  • Adjust ranking behavior without retraining models
  • Personalize weights per user segment or context
  • Rapidly respond to quality issues by adjusting weights

🧮 Score Aggregation Algorithm

The final score for each tweet is computed through a sophisticated multi-step process:

📁 /home-mixer/server/src/main/scala/com/twitter/home_mixer/util/RerankerUtil.scala
📁 /home-mixer/server/src/main/scala/com/twitter/home_mixer/functional_component/scorer/WeighedModelRerankingScorer.scala

Step 1: Per-Head Max Normalization

For each engagement signal i (1 to 15):
  max_score_i = max(score_i across all candidates)

For each candidate c and signal i:
  normalized_score_c,i = score_c,i / max_score_i

Purpose: Prevents a single high-scoring signal from dominating the final score. Each signal is scaled to a 0-1 range relative to the best candidate for that signal.

↓

Step 2: Apply Weights

For each candidate c and signal i:
  if weight_i >= 0 OR useWeightForNeg:
    weighted_score_c,i = normalized_score_c,i × weight_i
  else:
    // Special negative signal handling
    if (normalized_score_c,i > negThresholdNormalized) OR
       (score_c,i > negThresholdConstant):
      weighted_score_c,i = weight_i  // Full negative weight
    else:
      weighted_score_c,i = 0  // Ignore below threshold

Purpose: Negative signals (like Negative Feedback) have threshold-based application to avoid over-suppression.

↓

Step 3: Aggregate Weighted Scores

For each candidate c:
  combined_score_c = Σ(weighted_score_c,i for i=1 to 15)
↓

Step 4: Normalize by Total Weights

positive_weight_sum = Σ(weight_i where weight_i > 0)
negative_weight_sum = |Σ(weight_i where weight_i < 0)|
total_weight_sum = positive_weight_sum + negative_weight_sum

For each candidate c:
  if total_weight_sum == 0:
    final_score_c = max(combined_score_c, 0)
  else if combined_score_c < 0:
    final_score_c = (combined_score_c + negative_weight_sum) / total_weight_sum × ε
  else:
    final_score_c = combined_score_c + ε

where ε = 0.001 (epsilon for precision)
↓

Step 5: Sort Candidates

ranked_candidates = sort(candidates by final_score_c, descending)

Output: Candidates ranked by predicted engagement likelihood

🎭 Contextual Ranking Variations

The ranking algorithm adapts based on multiple contextual factors:

1. Video-Specific Logic

  • 10-Second Threshold: Video Quality View only applies if video ≥10 seconds
  • Dwell Exclusion: Dwell metric excluded for eligible video tweets
  • Immersive Mode: Different scoring for fullscreen video viewing
  • Binary Scheme: Optional constant value instead of probability for VQV

2. In-Network vs Out-of-Network

Aspect In-Network (Following) Out-of-Network (Discovery)
Primary Source Earlybird Search Index UTEG, SimClusters, Real Graph
Social Proof Not required "Liked by [connections]"
Scoring Earlybird model scores Real Graph × 1.0 + Earlybird × multiplier
Trust Level Higher (followed authors) Lower (requires more signals)

3. Device & User Context

  • Device Type: Different thresholds for mobile vs desktop
  • User Preferences: Video preferences affect VQV weighting
  • Premium Status: May affect content diversity ratios
  • Feedback History: 14-day window for "See Fewer" fatigue

4. Temporal Context

  • Time Decay: Controlled via RequestRankDecayFactorParam (default 0.95)
  • Recency Bias: Recent tweets boosted in Earlybird scoring
  • Real-time Aggregates: Hourly engagement stats influence scoring

🔀 Alternative Scoring: Phoenix Model

Twitter also has an alternative ranking system called Phoenix that uses different action mappings.

📁 /home-mixer/functional_component/scorer/PhoenixModelRerankingScorer.scala
Phoenix Action Mapped Engagement Description
SERVER_TWEET_FAV Favorite Like action
SERVER_TWEET_REPLY Reply Reply action
SERVER_TWEET_RETWEET Retweet/Quote Amplification action
CLIENT_TWEET_PHOTO_EXPAND Click Engagement Photo/media click
CLIENT_TWEET_VIDEO_QUALITY_VIEW Video View Quality video watch
CLIENT_TWEET_BOOKMARK Bookmark Save for later
CLIENT_TWEET_SHARE_* Share Multiple share types
⚠️ Phoenix vs Production: Phoenix can use production model scores as fallback via UseProdInPhoenixParams. This hybrid approach enables gradual migration and A/B testing between scoring systems.

📊 Score Aggregation Example

Example: Calculating Final Score for Tweet A

Given ML Predictions:
P(favorite) = 0.45
P(retweet) = 0.12
P(reply) = 0.08
P(dwell) = 0.65
P(negative_feedback) = 0.02
// Other signals: 0.1-0.3 range
Step 1: Per-Head Max Normalization
Assume across all candidates:
max(P(favorite)) = 0.85
max(P(retweet)) = 0.40
max(P(dwell)) = 0.90

Normalized scores for Tweet A:
norm_fav = 0.45 / 0.85 = 0.529
norm_rt = 0.12 / 0.40 = 0.300
norm_dwell = 0.65 / 0.90 = 0.722
Step 2: Apply Weights
Assume weights (hypothetical):
w_fav = 1000
w_rt = 1200
w_dwell = 500
w_neg = -5000

Weighted scores:
weighted_fav = 0.529 × 1000 = 529
weighted_rt = 0.300 × 1200 = 360
weighted_dwell = 0.722 × 500 = 361
weighted_neg = 0 // Below threshold
Step 3: Aggregate
combined_score = 529 + 360 + 361 + ... = 2,847
Step 4: Add Epsilon
final_score = 2,847 + 0.001 = 2,847.001

Result: Tweet A receives a final score of 2,847.001 and is ranked accordingly.

🔬 Advanced Features

Bias/Debias Per-signal bias correction parameters
Threshold Filters Normalized & constant negative thresholds
Multi-Model Phoenix + Production ensemble
A/B Testing Feature-switch gated experiments
💡 Why This Architecture is Powerful:
  • Flexibility: Weights adjustable without retraining → rapid iteration
  • Interpretability: Each signal's contribution is explicit and measurable
  • Multi-Objective: Balances 15 different engagement goals simultaneously
  • Context-Aware: Different strategies for different content types/user contexts
  • Testable: Easy A/B testing of weight configurations
  • Safety-Aware: Negative feedback signal actively suppresses low-quality content
