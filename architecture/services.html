🎯 Data Layer Services

Tweetypie

Purpose: Core tweet read/write service

  • Handles all tweet operations (create, read, delete)
  • Fetches from Manhattan database or Twemcache
  • Hydrates tweet data from multiple backends
  • Key packages: backends/, repository/, hydrator/, handler/
Unified User Actions (UUA)

Purpose: Real-time user action stream

  • Kafka-based architecture for action events
  • Tracks: favorites, retweets, replies, bookmarks, video views
  • Replicated to HDFS, GCP Pubsub, GCS, BigQuery
  • Components: Adapter, Kafka utilities, Service deployment
User Signal Service (USS)

Purpose: Centralized platform for user signals

  • Explicit signals: likes, retweets, replies
  • Implicit signals: clicks, views, profile visits
  • Used by all downstream ranking systems

🤖 ML & Embeddings Layer

Navi (ML Serving)

Purpose: High-performance Rust-based ML serving

  • gRPC API compatible with TensorFlow Serving
  • Supports: TensorFlow, ONNX Runtime, PyTorch
  • Batch prediction for efficient GPU utilization
  • Used for heavy ranking inference
SimClusters

Purpose: Community detection & sparse embeddings

  • 145,000 communities covering 20M+ users
  • KnownFor, InterestedIn matrices
  • Real-time tweet embeddings via Summingbird
  • Daily batch jobs via Scalding
Representation Manager (RMS)

Purpose: Embedding serving facade

  • Centralized access to SimClusters, TwHIN embeddings
  • Caching layer for fast retrieval
  • Interface to multiple storage backends
Real Graph

Purpose: User interaction prediction

  • Gradient boosting classifier
  • Predicts user-to-user interaction probability
  • Daily batch computation (BigQuery ML, SCIO)

🎯 Candidate Generation Layer

Earlybird

Purpose: Real-time search and indexing

  • Apache Lucene-based
  • Three clusters: realtime (7 days), protected, archive
  • 50+ RPS per shard with low latency
  • Feature Update Service for real-time engagement counts
GraphJet Services

Purpose: In-memory bipartite graphs

  • User-Tweet Graph (UTG)
  • User-Tweet-Entity Graph (UTEG)
  • User-Video Graph (UVG)
  • User-User Graph
  • Real-time updates via Kafka streaming
CR-Mixer

Purpose: Candidate generation orchestrator

  • Routes to appropriate similarity engines
  • Combines multiple candidate sources
  • Light ranking and filtering
  • Versioning and feature switches
Follow Recommendations Service (FRS)

Purpose: User and tweet recommendations

  • 5-stage pipeline: fetch, filter, rank, transform, truncate
  • Customizable per display location
  • Provides both users and their tweets
SimClusters ANN

Purpose: Approximate nearest neighbors

  • Approximate cosine similarity (6% of brute force)
  • 6,000+ RPS throughput
  • Multiple model versions (prod, experimental)

🎨 Framework Layer

Product Mixer

Purpose: Reusable recommendation framework

  • Pipeline-based architecture (Product, Mixer, Recommendation, Candidate, Scoring)
  • 200+ reusable components (selectors, filters, transforms)
  • Shared library for common integrations
  • Powers Home-Mixer, Pushservice, etc.
Home-Mixer

Purpose: Main timeline orchestrator

  • For You and Following timelines
  • 22+ candidate pipelines
  • Feature hydration (~6,000 features)
  • ML scoring via Navi
  • Mixing with ads, who-to-follow
TimelineRanker (Legacy)

Purpose: Relevance-scored tweets

  • Integrates Search Index + UTEG
  • Used by Home Mixer as backup
  • Interacts with Social Graph Service

🛡️ Safety & Quality Layer

Visibility Library

Purpose: Content filtering rule engine

  • 15+ visibility policies
  • Actions: Drop, Tombstone, Interstitial, Downrank
  • Safety labels and conditions
  • Legal compliance support
Trust & Safety Models

Purpose: ML-based content moderation

  • pNSFWMedia: Image NSFW detection
  • pNSFWText: Text NSFW detection
  • pToxicity: Toxic content detection
  • pAbuse: Abusive content detection

🔌 Communication & Data Flow

RPC: Thrift
  • Primary communication protocol
  • Strongly-typed interfaces
  • Service definitions in src/thrift/
Streaming: Kafka
  • User action streams (UUA)
  • GraphJet updates (Recos-Injector)
  • Real-time embeddings (SimClusters)
Storage
  • Manhattan: Distributed database (tweets, user data)
  • Memcached: Caching layer
  • HDFS: Batch job storage
  • BigQuery: Data warehouse
