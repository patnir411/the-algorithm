🌐 GraphJet: In-Memory Bipartite Graphs

📁 /src/scala/com/twitter/recos/user_tweet_entity_graph/

Architecture

Multi-segment power-law bipartite graphs for real-time recommendations.

Configuration:
  maxNumSegments: 5
  maxNumEdgesPerSegment: 64M (2^26)
  expectedNumLeftNodes: 16M (users)
  expectedNumRightNodes: 16M (tweets)
  leftPowerLawExponent: 16.0 (steep)

Edge Type Encoding (4 bits):
  CLICK = 0
  FAVORITE = 1
  RETWEET = 2
  REPLY = 3
  TWEET = 4
  
Edge Storage:
  edgeArray = [nodeId | (edgeType << 28), ...]
  Masks: 0x0FFFFFFF (28 bits for node), top 4 bits for type

Update Mechanism

Real-time Updates via Kafka:
1. Live Writer Thread → Current segment
2. Catch-up Writers (N-1) → Historical segments
3. Queue: ConcurrentLinkedQueue (1024 semaphore)
4. Bootstrap: Several hours of backfill

Segment Lifecycle:
- New segment when current reaches 64M edges
- When 5 segments reached → drop oldest
- Enables hot (real-time) + cold (batch) data

🎯 SimClusters: Community Detection

📁 /src/scala/com/twitter/simclusters_v2/

Approximate Cosine Similarity Algorithm

Step 1: Source Embedding
  userEmbedding = Top 50 clusters

Step 2: Candidate Fetching  
  For each cluster: fetch top 400 tweets
  → ~900 unique tweets total

Step 3: Approximate Matrix
  Build sparse matrix (only top 50 clusters)

Step 4: Dot Product
  approximateScore = userEmbed · tweetApproxEmbed

Step 5: Top-K Selection
  Select top 200 by approximate score

Step 6: True Cosine Similarity
  Fetch full embeddings for top 200
  trueScore = cosine(userEmbed, tweetFullEmbed)
  
Step 7: Filter
  Return tweets where trueScore >= 0.7

Efficiency: 900 fetches vs 15,000 (6% of brute force!)

Normalization Methods

  • Cosine: score / (||user|| × ||tweet||)
  • Log-Cosine: score / (logNorm_user × log(1 + norm_tweet))
  • Dot Product: Raw score

📊 PageRank / Tweepcred

📁 /src/scala/com/twitter/graph/batch/job/tweepcred/WeightedPageRank.scala

Algorithm

Parameters:
  ALPHA = 0.1 (jump probability)
  THRESHOLD = 0.001 (convergence)
  MAXITERATIONS = 20

One PageRank Iteration:
  For unweighted:
    PR_next(i) = Σ(PR(j) / degree(j)) for all j→i
    
  For weighted:
    PR_next(i) = Σ(PR(j) × w(j,i) / totalWeight(j))
    
  Random jump:
    deadPR = (1 - Σ PR_next(i)) / N
    randomPR(i) = userMass(i) × ALPHA + deadPR × (1-ALPHA)
    
  Final:
    PR_output(i) = randomPR(i) + PR_next(i) × (1-ALPHA)

Convergence:
  if totalDiff < THRESHOLD or iteration >= 20:
    Extract Tweepcred scores
  else:
    Continue to next iteration

🔍 Graph Traversal Patterns

1. Left-Node Sampling (UTEG)

Goal: Find users who engaged with tweet T

sampledUsers = []
iterator = graph.getRandomRightNodeEdges(T, maxSamples=100)

while iterator.hasNext:
  userId = iterator.nextLong()
  degree = graph.getLeftNodeDegree(userId)
  
  # Filter power users
  if degree < 100:
    sampledUsers.append(userId)

return sampledUsers

2. Right-Node Fetching

Goal: Find tweets from sampled users

relatedTweets = []
for userId in sampledUsers:
  iterator = graph.getLeftNodeEdges(userId)
  
  while iterator.hasNext:
    tweetId = iterator.nextLong()
    edgeType = iterator.currentEdgeType()
    
    # Filter by engagement type
    if edgeType in [FAVORITE, RETWEET]:
      relatedTweets.append(tweetId)

return relatedTweets.distinct()

3. Co-occurrence Scoring

Goal: Score candidates by co-engagement

cooccurrence = Counter(relatedTweets)

candidates = []
for tweetId, count in cooccurrence.items():
  degree = graph.getRightNodeDegree(tweetId)
  
  # Filters
  if count >= minCooccurrence (3) and degree >= minDegree (50):
    # Log-cosine score
    score = count × queryDegree / log(degree) / sampleSize
    candidates.append((tweetId, score))

return sorted(candidates, key=score, reverse=True)

🎓 Key Insights

Why Multiple Graph Algorithms?

  • SimClusters: Interpretable communities, sparse, efficient ANN
  • GraphJet: Real-time updates, fresh engagement signals
  • PageRank: Global reputation, anti-spam signal
  • Real Graph: Personalized user-user similarity

Real-time vs Batch Tradeoff

  • Real-time (GraphJet): Fresh (48h window), low latency (~50ms)
  • Batch (SimClusters): Comprehensive (all history), daily updates
  • Hybrid: Best of both worlds - fresh signals + stable patterns
