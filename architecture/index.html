High-Level Architecture Flow

1. User Request

Client requests "For You" timeline → Home-Mixer service

↓

2. Query Feature Hydration

Fetch user context: social graph, preferences, demographics, engagement history (~100 features)

↓

3. Candidate Generation (Parallel)

10+ sources fetch candidates simultaneously:

  • Earlybird Search (in-network)
  • UTEG (out-of-network with social proof)
  • SimClusters ANN (community-based)
  • Real Graph (user similarity)
  • CR-Mixer (orchestrator)

~1,500 - 4,000 candidates

↓

4. Candidate Feature Hydration

Enrich each candidate with ~6,000 features:

  • Author features (reputation, verification)
  • Content features (text, media, entities)
  • Engagement features (likes, RTs, replies)
  • Graph features (user-author similarity)
  • Embedding features (SimClusters, TwHIN)
  • Real-time aggregates (hourly stats)
↓

5. ML Scoring (Navi Model Serving)

Neural network predicts 15 engagement probabilities per tweet:

  • Like probability (weight: dynamic)
  • Retweet probability
  • Reply probability
  • Video watch probability
  • Click probability
  • ...and 10 more signals
↓

6. Score Aggregation & Ranking

Weighted sum with per-head normalization:

finalScore = Σ(signal_i × weight_i) + ε

Candidates sorted by final score (descending)

↓

7. Filtering & Quality Control

Apply 50+ filters:

  • Safety filters (NSFW, spam, abuse)
  • Deduplication (semantic clustering)
  • Author diversity (exponential decay)
  • Content balance (in/out network ratio)
  • Visibility rules (blocks, mutes)
↓

8. Mixing & Assembly

Inject additional content:

  • Ads (organic positions)
  • Who-to-Follow modules
  • Trending topics
  • Stories/Fleets
  • Conversation modules

~35 tweets in final response

↓

9. Response Marshalling

Serialize to URT (Universal Recommendation Timeline) format → Client

⚡ Key Performance Characteristics

  • Latency: ~200-500ms end-to-end for timeline generation
  • Scale: 50+ RPS per Earlybird shard, 6000+ RPS for SimClusters ANN
  • Parallelization: Candidate sources run in parallel via Stitch framework
  • Feature Hydration: Batch fetching from 20+ services concurrently
  • Real-time Updates: GraphJet processes streaming Kafka events with ~50ms delay
  • Batch Processing: Daily jobs for embeddings (SimClusters, Real Graph)

🔍 What Makes This Algorithm Unique

  • Hybrid Architecture: Combines real-time streaming (GraphJet) with batch ML (SimClusters)
  • Multi-Task Learning: Single model predicts 15 different engagement types
  • Social Proof: Out-of-network recommendations show which connections engaged
  • Extreme Flexibility: All weights dynamically adjustable via feature switches (A/B testing)
  • Graph-Powered: Multiple specialized graphs (User-Tweet, User-Video, User-User, UTEG)
  • Embedding-Rich: SimClusters (sparse), TwHIN (dense), Real Graph, author/tweet embeddings
  • Safety-First: Multiple ML models for NSFW, spam, toxicity with rule-based enforcement
