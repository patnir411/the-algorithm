🧠 Heavy Ranker Model

ClemNet Architecture NEURAL NETWORK

Multi-task learning neural network for push notification ranking. Predicts both open probability and engagement likelihood.

📁 /pushservice/src/main/python/models/heavy_ranking/lib/model.py
📁 /pushservice/src/main/python/models/heavy_ranking/deep_norm.py

Architecture

Input Features (~250 features)
    ↓
Dense Branch (Continuous Features)
  - Z-score normalization
  - Dense layers: 1024 → 512 → 256 → 128
  - Batch normalization with renorm
  ↓
Sparse Branch (Discrete Features)
  - Hash space: 2^18 = 262,144 dims
  - Embedding size: 50 dims
  - Full sparse layers
  ↓
Residual Blocks (Stacked)
  - Dense layers + 1D Convolution (kernel=3, filters=5)
  - Batch normalization
  - Residual connections
  - LeakyReLU activation
  ↓
Multi-Task Heads
  - OONC (Open Or Ntab Click): weight 0.9
  - Engagement: weight 0.1
  ↓
Output: Cumulative product of sigmoids
  final_score = cumprod(sigmoid(logits))
Input Features ~250
Dense Units 1024→128
Embedding Dim 50
Tasks 2 (OONC, Engagement)

Training Configuration

  • Loss: Binary cross-entropy with sigmoid
  • Optimizer: Gradient Descent with learning rate scheduling
  • Metric: PR-AUC (Precision-Recall Area Under Curve)
  • Early Stopping: Based on pr_auc_unweighted_OONC
  • Task Weights: OONC=0.9, Engagement=0.1

🌐 SimClusters Embeddings

Community Detection SPARSE EMBEDDING
📁 /src/scala/com/twitter/simclusters_v2/
📁 /simclusters-ann/

Overview

Sparse, interpretable embeddings representing Twitter communities. 145,000 communities covering 20M+ producers.

Key Matrices

Matrix Dimensions Description Update Frequency
KnownFor (V) Producers × Communities Which communities producers belong to Daily
InterestedIn (U) Users × Communities Which communities users are interested in Daily
Tweet Embeddings Tweets × Communities Tweet community affiliation (from favorites) Real-time
Topic Embeddings Topics × Communities Topic-community relationships Daily

Computation Pipeline

Step 1: Community Detection (Scalding Job)
  - Read user follow graph
  - Compute producer-producer similarity
  - Run Metropolis-Hastings sampling
  - Output: KnownFor matrix (top 100 communities per producer)

Step 2: InterestedIn Calculation
  - For each user: aggregate followed producers' KnownFor
  - Weight by follow recency and engagement
  - Output: InterestedIn matrix (top 100 communities per user)

Step 3: Tweet Embedding (Real-time)
  - Monitor favorite events via Kafka
  - Aggregate favoriters' InterestedIn vectors
  - Update tweet embedding incrementally
  - Output: Tweet → Communities mapping

Step 4: Representation Manager
  - Serve embeddings online via RMS
  - Cache in Manhattan/Memcached
  - Query interface for downstream services
Communities 145,000
Producers Covered 20M+
Top-K per Entity 50-100
Embedding Type Sparse

🔗 Real Graph Model

User Interaction Prediction GRADIENT BOOSTING
📁 /src/scala/com/twitter/interaction_graph/

Purpose

Predicts probability of user-to-user interaction (follows, mentions, engagement likelihood).

Features

  • Follow Scores: L2-normalized by follower count
  • Favorite Scores: Half-life decay (100 days), log-normalized
  • Engagement Counts: Follower count, faver count
  • Temporal: Recency-weighted interactions

Data Structure

struct NeighborWithWeights {
  neighborId: i64
  isFollowed: bool
  followScoreNormalizedByNeighborFollowersL2: double
  favScoreHalfLife100Days: double
  logFavScore: double
  logFavScoreL2Normalized: double
}

struct NormsAndCounts {
  userId: i64
  followerL2Norm: double
  faverL2Norm: double
  followerCount: i64
  faverCount: i64
}
Model Type Gradient Boosting

🎯 Feature Engineering Pipeline

Feature Categories (6,000+ Total)

Category Count Examples Processing
Author Features ~500 Follower count, verification, reputation, abuse strikes Batch normalization
Content Features ~1,000 Text embeddings, entities, media, language, length Transformer encodings
Engagement Features ~300 Like/RT/reply counts, velocity, age-adjusted Log transform + clipping
Graph Features ~800 Real Graph scores, social connections, intersection counts L2 normalization
Embedding Features ~2,000 SimClusters (sparse), TwHIN (dense), Transformer Dot products, cosine sim
Temporal Features ~200 Tweet age, hour of day, day of week, recency Cyclical encoding
Real-time Aggregates ~600 Hourly engagement stats, trending scores Windowed aggregation
Safety Features ~600 NSFW scores, spam scores, toxicity, abuse Multi-model ensemble

Feature Processing Methods

Continuous Features

1. Filter NaN and Infinity values
2. Sign-magnitude log transform: sign(x) × log(|x| + 1)
3. Batch normalization (momentum=0.9999, renormalization)
4. Clip to range [-5, 5]

Sparse Features

1. Hash to fixed bit space (18 bits = 262,144 dimensions)
2. Full sparse embedding layer
3. Z-score normalization for sparse continuous features
4. Embedding size: typically 50 dimensions

🚀 Model Serving: Navi

High-Performance ML Serving RUST
📁 /navi/

Architecture

  • Language: Rust for high performance
  • API: gRPC compatible with TensorFlow Serving
  • Plugin System: TensorFlow (mature), ONNX, PyTorch (experimental)
  • Batch Inference: Processes multiple candidates simultaneously

Workflow

1. Feature Hydration
   Features → DataRecord format conversion

2. Batch Preparation
   Group candidates for efficient GPU utilization

3. Model Inference
   Navi gRPC → TensorFlow/ONNX runtime

4. Score Extraction
   Parse predictions → Feature maps

5. Return to Ranker
   15 engagement probabilities per candidate
Latency 50-100ms
Batch Size 100-500
Throughput High (GPU)

🎓 Key Insights

Why This ML Architecture Works

  • Multi-Task Learning: Single model predicts 15 signals → shared representations
  • Hybrid Embeddings: Sparse (SimClusters) + Dense (TwHIN) capture different aspects
  • Feature Richness: 6,000 features ensure comprehensive signal capture
  • Real-time + Batch: Fresh data (hourly aggregates) + stable patterns (SimClusters)
  • Interpretability: SimClusters provide human-understandable communities
  • Performance: Navi (Rust) + GPU acceleration for low latency at scale
